# 数据集说明：NASA C-MAPSS 涡轮风扇发动机退化数据

> 本文件专门讲「**数据集该怎么正确理解与使用**」。建模代码在 `tools/preprocess.py`，
> 但很多 RUL 项目的坑不在模型，而在对这份数据的语义理解——本文把最容易写错的地方讲清楚。
> 所有数字均来自本项目实际使用的 `datasets/` 镜像数据，已逐项核验。

---

## 1. 它是什么

- **C-MAPSS**（Commercial Modular Aero-Propulsion System Simulation）：NASA 发布的涡扇发动机
  **运行至失效（run-to-failure）** 仿真数据集，是预测性维护 / 剩余使用寿命（RUL, Remaining Useful Life）
  预测领域最经典的公开基准之一。
- 源自 **2008 年首届国际预测与健康管理大会（PHM08）** 竞赛数据。
- 本项目仅用于算法验证与学习，原始数据版权归 NASA PCoE 所有。

---

## 2. 文件清单

每个子集 `FD00X`（X = 1/2/3/4）包含三份数据文件 + 说明文件：

| 文件 | 说明 |
| :--- | :--- |
| `train_FD00X.txt` | 训练集：每台发动机**完整退化轨迹**（跑到失效） |
| `test_FD00X.txt`  | 测试集：每台发动机**在失效前被截断**的轨迹 |
| `RUL_FD00X.txt`   | 测试集每个引擎的**真实剩余寿命**（预测目标真值） |
| `readme.txt`      | 官方字段说明 |
| `Damage Propagation Modeling.pdf` | 配套参考论文 |

## 3. 数据格式（26 列，空格分隔）

每一行 = 一台发动机在一个运行循环（cycle）的快照：

| 列 | 名称 | 含义 |
| :--- | :--- | :--- |
| 1 | `unit`     | 发动机编号（同一编号 = 同一台机的连续时间线） |
| 2 | `cycle`    | 运行周期数（时间轴，从 1 递增） |
| 3–5 | `setting_1~3` | 三个工况设置（风扇转速 / 马赫数 / 高度温度等环境参数） |
| 6–26 | `sensor_1~21` | 21 个传感器测量（温度、压力、转速等，含噪声） |

**真实样例**（本仓库 `train_FD001.txt` 第 1 行）：

```
1  1  42  0.00  840.0  100.0  518.67  641.82  1589.70  ...  (共 26 列)
│  │  └─ setting 列（FD001 单工况下全部恒定 = 42/0/840）
│  └──── cycle = 1（第 1 个循环）
└─────── unit = 1（1 号发动机）
```

读数据的几个直觉：
- **`unit` 切换 = 换一台机器**：开头全 `1`，等到出现 `2` 说明 1 号机已报废，开始记录 2 号机。
- **`cycle` 递增 = 时间推进**：1 号机从 1 一直增长到失效圈。
- **传感器随老化漂移**：同一台机从早期到晚期，部分传感器值单调变化（如 engine 1 的某传感器从 `641.82` 一路降到 `633.82`）。
- **含传感器噪声**：同一工况下相邻周期同一传感器也不是完全相等（如 `518.67` vs `518.68`），这是模拟真实噪声。
- **初始磨损差异**：1 号机与 2 号机第 1 周期读数本就略有不同，属正常个体差异，不是故障。

## 5. ⚠️ 最关键：train / test / RUL 的正确关系

这是整份数据最容易理解错的地方，**务必看清**：

### 5.1 训练集与测试集是「两批不同的机器」

`train_FD001` 里的 1 号机 和 `test_FD001` 里的 1 号机 **不是同一台物理发动机**。
- 训练集：100 台**独立**发动机，各自跑到失效（RUL 从大到 0）。
- 测试集：另 100 台**独立**发动机，在失效**之前**的某个时间点被停止记录。

所以**不能**用「训练 1 号机失效圈 − 测试 1 号机最后圈」来算 RUL。下面用本仓库真实数字说明：

| 项目（engine 1, FD001） | 数值 |
| :--- | :--- |
| train 1 号机失效周期（最大 cycle） | **192** |
| test 1 号机最后记录周期 | **31** |
| `RUL_FD001.txt` 第 1 行（真值） | **112** |
| （错误算法）192 − 31 | 161 **≠ 112** ❌ |

### 5.2 正确的语义

- **测试集 RUL 真值** = 「该测试引擎在**最后观测圈之后**，还能继续运行的圈数」。
- 因此 test 1 号机的**总寿命** = 已观测 31 圈 + 剩余 112 圈 = **143 圈**（这是它自己的寿命，与 train 1 号机的 192 圈无关）。
- **训练集没有单独的 RUL 文件**：因为训练机跑到了失效，其每个 cycle `t` 的标签就是
  `RUL(t) = 该机最大 cycle − t`（最后一个循环 RUL=0）。

> 一句话记忆：**RUL 文件只服务测试集；训练集的 RUL 由「最大圈数倒数」现场生成；train 和 test 是两套机队。**

### 5.3 为什么测试集比训练集难

测试引擎是在退化的**不同阶段**被截断的（本仓库 FD001 测试 RUL 均值 ≈ 75.5、标准差 ≈ 41.6），
模型要在「还没看到完整退化曲线」的情况下预测剩余寿命——这正是 C-MAPSS 的核心难点，
也解释了为什么模型在测试集上的误差通常高于训练集。

### 5.4 RUL 标签裁剪（clip）

实际建模中常把 RUL 标签按 `max_rul`（本项目 = 125）裁剪：超过 125 的部分统一记为 125。
原因：生命早期（RUL 很大时）退化信号极弱、预测意义小，裁剪可让模型更聚焦「真正进入退化区」的样本，降低早期样本对损失的支配。
`preprocess.py` 中 `clip_rul` 参数即控制此行为；想看裁剪前后分布可用 `tools/eda.py`。

## 6. 本项目预处理如何对应（防踩坑）

`tools/preprocess.py` 的每一步都针对上面的数据特性设计：

| 步骤 | 做法 | 对应数据特性 / 防坑点 |
| :--- | :--- | :--- |
| 特征选择 `select_features` | 剔除训练集方差为 0 的恒定列 | FD001 下 `setting` 全恒定、6 个传感器恒定 → 共剔除 6 列；**按子集独立选**，FD002/004 多工况会自动保留 setting（选中 24 特征） |
| 归一化 | **仅用训练集**拟 z-score 统计量 | 防止测试集信息泄漏到训练；推理时复用同一均值/标准差 |
| 滑窗 | 取最近 `window=30` 个 cycle 作输入 | 用局部退化趋势预测，而非单点快照 |
| RUL 标签 | 训练机倒数生成 + clip=125 | 见 5.2 / 5.4 |
| 测试样本 | 每台测试机**仅取最后一段窗口** | 对应「最后观测圈之后预测 RUL」，与真值文件一一对应 |

## 7. 数据获取与校验

```bash
# 本仓库已附带 datasets/ 下的 12 个 txt；若需自行下载，可用公开镜像：
# https://github.com/NicolasDeHorta/CMAPSSData
```

拿到数据后建议先校验，避免后续静默错位：

```python
import numpy as np
for s in ["FD001","FD002","FD003","FD004"]:
    test = np.loadtxt(f"datasets/test_{s}.txt")
    rul  = np.loadtxt(f"datasets/RUL_{s}.txt")
    n_engines = int(test[:, 0].max())
    assert n_engines == rul.shape[0], f"{s}: 测试引擎数({n_engines}) != RUL行数({rul.shape[0]})"
    assert test.shape[1] == 26, f"{s}: 列数应为 26"
print("OK: 各子集自洽")
```

## 8. 常见误用清单

1. ❌ 把 train 和 test 的同一 `unit` 当成同一台机器来减周期算 RUL。
   ✅ 它们是两套机队；测试 RUL 直接读 `RUL_FD00X.txt`。
2. ❌ 用全量数据（含测试集）拟归一化统计量。
   ✅ 只用训练集拟，推理时复用，杜绝泄漏。
3. ❌ 忽略 `setting` 在多工况子集（FD002/FD004）里的信息，误当恒定剔除。
   ✅ 按子集独立选特征。
4. ❌ 不核对「测试引擎数 == RUL 行数」，换数据源后静默错位。
   ✅ 下载后先跑第 7 节的校验。
5. ❌ 测试集也对每个 cycle 预测并求平均。
   ✅ 测试集只取每台机最后一段窗口，与 RUL 真值一一对应。
